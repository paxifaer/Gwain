# 按钮↔接口映射表（ui-api-map）

界面上每个可操作元素一行。这张表是「前端按钮与后端不一致」的直接防线：按钮、路径、协议三方任何一方变动，此表必须同步，否则验收不过。

| 字段 | 说明 |
|---|---|
| ID | U-NN |
| 控件 | 按钮/开关/输入框 + `data-testid` 或稳定定位符 |
| 交互 | 点击/提交/自动刷新，触发条件 |
| 请求 | 调用哪个接口（引用契约表 ID） |
| 预期响应 | 成功时关键字段 |
| 预期 UI 反应 | 可观察变化：文案、状态、徽标、跳转 |
| 异常反应 | 409/504/断网/坏数据时用户看到什么 |
| 覆盖测试 | 哪条用例验证了这行 |

## 填写规则

- 「预期 UI 反应」必须可观察（文案或状态），不接受「处理成功」这类不可验证描述。
- 异常反应单独写：默认「toast 报错并保留原状态」也要写出来。
- 每行至少一条覆盖测试；没有测试覆盖的行标「待补」，验收不过。

## 示例（真实链路节选）

| ID | 控件 | 交互 | 请求 | 预期 UI 反应 | 异常反应 | 覆盖测试 |
|---|---|---|---|---|---|---|
| U-01 | 音响卡片「关闭音响」按钮 | 点击 | C-01 | 显示「已停止 N 条播报」；按钮恢复可点 | 409/504 时 toast 报错并显示失败行 | 页面测试：`stops the announcement through /api/argodog/audio/stop` |
