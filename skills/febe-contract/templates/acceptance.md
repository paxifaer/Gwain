# 验收标准模板（acceptance）

验收标准与需求逐条对应，单条单判。**未经用户在「批准记录」签字，不得开工、不得宣告完成。**

## 需求对应栏

| R-ID | 用户原始需求（逐字） | 对应验收条目 |
|---|---|---|
| R-01 | 「」（原话，不改写） | A-01、A-03 |

## 验收条目

每条一行，独立判定；复合条件拆开。

| 字段 | 说明 |
|---|---|
| A-ID | A-NN |
| 场景 | 在什么状态下做 |
| 前置 | 数据源、版本、设备状态 |
| 操作 | 具体动作（谁、点什么、调什么） |
| 期望 | 可观察结果，含数值与文案 |
| 证据层 | L0-L4（见 `test-boundaries.md`） |
| 反例 | 期望被拒绝/不得发生的现象（EXPECTED_REJECT） |
| 对应需求 | R-ID |
| 状态 | 待批准 / 已批准 / READY_FOR_USER_ACCEPTANCE |

## 批准记录

```text
批准人：（用户）
批准时间：
批准的需求版本：
批准范围：A-01 .. A-NN
变更记录：任何修改须重新走批准，旧证据作废
```

## 判定规则

- 全部条目 PASS 且反例全部 EXPECTED_REJECT，才允许写 `READY_FOR_USER_ACCEPTANCE`。
- 缺证据 = 未证明，不是 PASS。
- agent 不得写「验收通过」；最终验收属于用户。
