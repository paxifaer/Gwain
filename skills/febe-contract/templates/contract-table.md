# 接口契约表（contract-table）

每个跨端接口一行。字段命名与错误语义必须双端一致；写完后端实现不得单方面修改此表。

| 字段 | 说明 |
|---|---|
| ID | C-NN，验收与映射表引用它 |
| path | 完整路径，含前缀 |
| method | GET / POST / … |
| 请求 | schema：字段、类型、必填、默认值、约束 |
| 响应 | schema：成功字段、错误字段、可空性 |
| 计数定义 | 计数类字段的计数对象与单位（如「按 occurrence 计，正在播的段与其 occurrence 合计一次」）；无计数字段写「无」 |
| 错误语义 | 状态码 + 错误字段取值 + 用户可见文案的来源 |
| 幂等 | 是/否；重复调用的行为 |
| 副作用 | 会改变什么状态；是否触发播放/写盘/发指令 |
| 超时与重试 | 客户端超时、可否重试、重试语义 |
| 负责人/版本 | 后端归属、契约版本号 |

## 填写规则

- 一条接口一行；复合语义拆多行。
- 响应 schema 以生成器（如 `utoipa` 导出的 OpenAPI）为准，本表引用 `openapi.json` 的 schema 名，不复制字段清单。
- 「计数定义」必填：`stopped`/`resumed`/`count` 这类字段必须写清按什么计数、重复调用怎么算，否则语义歧义直接判 FAIL。
- 错误语义必须写「用户看到什么」，不只写状态码。
- 副作用栏禁止写「无」了事：写清楚没有副作用，或写出具体副作用。

## 示例（真实链路节选）

| ID | path | method | 请求 | 响应 | 错误语义 | 幂等 | 副作用 |
|---|---|---|---|---|---|---|---|
| C-01 | `/api/argodog/audio/stop` | POST | `{}` 或 `{request_id}` | `AudioStopResponse{ok, stopped, error, request_id, operation, source}` | 409 忙；504 超时（`detail.availability=unknown-result`） | 是（重复调用返回 `stopped:0`） | 静默当前播报与本次触发；不改告警状态 |
