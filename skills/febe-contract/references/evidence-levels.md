# 证据分级与假绿拒绝规则

## 证据分级

| 级别 | 含义 | 例子 | 常见越界 |
|---|---|---|---|
| L1 mock | 模拟数据/模拟服务 | 合成数据喂入、mock transport | 把 mock 结果当真实能力 |
| L2 软件链路 | 真实服务间的软件观测 | curl 响应、测试输出、日志 | 用「无报错」代替正向证据 |
| L3 真实客户端 | 真实浏览器/客户端完整链路 | Playwright 操作记录、网络面板 | 组件测试顶替浏览器 |
| L4 物理观测 | 真实设备/物理世界 | 人耳听、录音、仪器读数 | 用软件状态推断物理效果 |

规则：**结论的证据级别不得低于该验收条目要求的级别。** 不足即「未证明」。

## 三条硬性推论禁令

1. 「日志没有 warn」≠ 功能正常；正向证据要看到功能发生。
2. 「状态字段显示 ACTIVE/已停止」≠ 物理世界符合；L4 结论需要 L4 证据。
3. 「测试全绿」≠ 用户目标达成；验收必须逐条对照需求。

再加两条常见越界：

4. 「进程活着」≠ 链路可用；数据源→订阅→界面要逐跳验证（端点写错的进程也能健康运行）。
5. mock/合成数据的来源必须在界面或日志里持续标识；用户误把模拟当真实即事故。

## 假绿拒绝规则（对验收记录直接判 FAIL）

- 0 执行或执行数少于要求数。
- 必测用例被 `skip` / `ignored` 仍在总数里报绿。
- 非零退出码被管道吞掉（保留每个命令的原始退出码）。
- 层级替代：浏览器检查顶替设备链路、静态分析顶替动态测试、mock 顶替真后端。
- 失败分支不可达且无强制触发手段。
- 只给结论不给原始输出/行号/退出码。

## 对抗验证者的取证格式

每条结论一行：

```text
- 结论：<证伪成功 / 未证伪> — 依据：<命令> — 期望:<...> — 实际:<...> — 退出码:<N> — 证据:<路径:行号>
```

禁止「我检查过没问题」这类无产出叙述。
